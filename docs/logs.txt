SECURITY DECISIONS — recorded deliberately:

1. ORDER SCOPING. /orders and /notifications filter to the signed-in shopper.
   The seeded orders belong to a named customer, so without this every new
   signup would read one customer's purchase history. Documented in-code as a
   privacy-hygiene measure, NOT an authorization boundary — the orders array is
   localStorage in the visitor's own browser, so there is no server withholding
   anything. VERIFIED in real Chrome: signing in as a second account in the same
   browser shows "No orders yet" and leaks no order id, including on the
   notifications page.

2. OPEN REDIRECT GUARD. /login takes ?redirect= so gated pages can bounce and
   return. That value is attacker-controlled, so safeRedirect() accepts only
   single-slash absolute paths — rejecting https://, protocol-relative //host,
   and /\host, which some browsers normalise to an external origin. Without it
   MarketHub's own sign-in page becomes a credible phishing hop. VERIFIED
   against 4 hostile values; all stayed on-origin, and /orders still works.

3. NO BANK DETAILS ON THE SELLER FORM. /vendor-register asks for GSTIN and PAN
   but never an account number or IFSC, and says why on the form. Payout details
   are described as collected after approval over a verified channel. The
   payouts tab states that bank details are not readable from the browser at
   all, not even masked.

4. SELLER ORDER VIEW IS MINIMAL. The vendor order table shows destination city
   and order contents, not the shopper's full address or profile. Seller Policy
   section "Shopper data you receive" states the same rule in words.

5. noindex, nofollow on /account, /orders, /notifications and /vendor. Personal
   and seller data should not be in a search index.

6. LOGOUT CLEARS ADDRESSES as well as the session — postal addresses and phone
   numbers in localStorage on a possibly-shared machine should not survive a
   sign-out.

7. THE SECURITY TAB SAYS THE QUIET PART. Rather than render a password form that
   implies protection, /account?tab=security carries a warning that sign-in
